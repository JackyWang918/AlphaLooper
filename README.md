# AlphaLooper

## 最新：普通订单确认（2026-09-22）

“提交并确认这一笔真实限价单”会在填表并点击买入/卖出后，等待普通订单确认弹窗，核对币种、限价方向、委托价、数量、成交额与本次指令一致，并读取预计手续费；买入含预计手续费仍受 50 U 上限约束。核对通过才点击一次“继续”，随后由订单巡检确认平台结果。验证码、风控、未知弹窗或字段不一致会停止；超时与后端重启不重放任何提交/确认动作。

这是新增的自动确认步骤，取代此前“额外交易确认弹窗全部由用户处理”的行为。后端需重启加载，刷新控制台后使用；新单开关仍默认关闭。仅隔离页面测试验证了确认点击，真实平台自动确认尚待用户验收。仅填表及只读检查入口保持不提交。

本地运行的 Binance Alpha 浏览器交易辅助工具。用户手动登录并处理验证，程序接收指定的交易对、买卖方向、价格和数量，通过浏览器执行操作，并展示执行状态与结果。

## 当前状态

基础工程已初始化，控制台支持启动独立持久化 Chrome、打开指定 Alpha 链接和刷新浏览器状态。浏览器由独立子进程管理，页面操作串行执行。SQLite 与 Alembic 已包含持久化模拟账本迁移。

已按中文 Alpha 页面的实际控件实现“仅填表并核对”，支持识别 USDT/USDC 计价币、切换买卖方向、填写价格和数量，再回读核对。另有默认关闭的实盘单笔提交入口，见文末；该入口仅隔离页面测试通过，真实平台待验收。行情试算和模拟策略见下文。控制台中的操作反馈仅保留在当前页面内存中；刷新后重新查询浏览器状态，不重放操作。

当前验证币种为 BSC 上的 DGAI，默认链接已填入控制台。未登录真实页面的买入填值与回读已验证；卖出切换被平台地区提示弹窗阻挡，需用户处理弹窗后继续实测。隔离测试页面上的买卖两侧与异常拦截已验证。登录后页面仍需用户看护验证。

本机初始化环境：Python 3.12.13（uv 管理）、uv 0.10.12、Node.js 24.14.1、npm 11.11.0。Python 版本约束与锁文件位于 `backend`，前端使用 npm 锁文件。

换机或开启新 Codex 会话时，先读 [项目目的与接续说明](docs/project-context.md)。详细设计见 [技术方案](docs/technical-plan.md)。根目录 [AGENTS.md](AGENTS.md) 提供接续阅读顺序和项目约定。

## 行情与策略试算

在控制台输入 BSC Alpha 链接，到“行情与策略研究”确认手续费假设并点击“获取行情并试算”。无需登录，支持已匹配交易对的 USDT/USDC 计价；其他链暂未适配。

- 展示已收盘 1 分钟 K 线、成交量、24 小时统计和六档盘口。
- 用窗口成交量加权均价和收盘价标准差计算挂价，参数可调，价格/数量按交易规则取整。
- 显式事件沙盒可验证 5 分钟撤单重挂、部分买入先转卖、每分钟 2% 检查、30 分钟持仓退出、达标清仓与 10 U 预算。
- 沙盒不自动推断成交，不发送浏览器交易指令；任务参数创建后锁定，修改需新建模拟任务；历史记录保留，刷新后可恢复。
- 盘口过期、网络失败或数据异常时停止试算，不使用旧行情冒充实时行情。竞价盘口交叉时暂停模拟新买入。

模型默认值、费用和预算口径见 [策略约定](docs/strategy.md)。这是研究工具，没有实现自动实盘交易。

### 行情网络配置

默认使用 httpx 直连。若本地网络需要代理，可将 `backend/.env.example` 复制为 `backend/.env`，设置：

```dotenv
ALPHALOOPER_HTTP_PROXY=http://127.0.0.1:7897
ALPHALOOPER_HTTP_TRANSPORT=curl
```

`curl` 是本机 Python TLS 不兼容时的可选方式，需要已安装 curl；它保持 HTTPS 证书校验，不携带登录 Cookie。公司机器已实测该方式可取回 DGAI 行情。代理地址应按家里网络调整，不能假定始终可用。

在 `backend` 中带环境文件启动：

```powershell
uv run --env-file .env uvicorn app.main:app --host 127.0.0.1 --port 18760
```

`.env` 不提交 Git。仅设置环境变量时，也可使用原有启动命令。行情接口为 `/api/research/preview`，模拟接口为 `/api/research/simulate`。

## 技术栈

| --- | --- |
| 后端 | Python、FastAPI |
| Python 项目与依赖管理 | uv，提交 `pyproject.toml` 和 `uv.lock` |

## 第一阶段

交付一个有界面的浏览器下单验证工具：

1. 启动可控制的 Chrome 窗口，用户手动登录及处理验证。
2. 接收用户输入的 Alpha 交易链接，识别并核对交易对。
3. 在控制台输入买卖方向、价格和数量。
4. 支持“仅填表”：自动填写并核对页面实际值，不提交。
5. 支持显式提交：提交指定订单，处理正常确认弹窗，展示提交结果。
6. 展示浏览器状态、任务状态、错误信息与操作记录。

提交成功与成交成功分别记录。提交结果未知时暂停，先核对已有订单，不自动重新提交。第一阶段不包含自动选币、行情策略、超时撤单重挂或夜间无人值守交易。

## 本地运行约定

使用两个终端分别运行前后端。首次运行或更新依赖后执行依赖同步与数据库迁移。

后端，在 `backend` 目录执行：

```powershell
uv sync --locked
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 18760
```

前端，在 `frontend` 目录执行：

```powershell
npm ci
npm run dev -- --host 127.0.0.1 --port 18761
```

访问地址为 `http://127.0.0.1:18761`，接口文档为 `http://127.0.0.1:18760/docs`。前端代理 `/api` 到后端。后端默认不启用自动重载，后续浏览器执行器将由后端管理。

使用本机 Chrome，不需要自行下载或匹配 ChromeDriver，也无需执行 `playwright install` 下载另一套浏览器。在 `backend` 目录执行 `uv run python scripts/check_browser.py` 可检查本机 Chrome 启动、输入和点击能力；该检查使用无头临时会话，不访问外部网站或使用登录数据。实际交易页面的有界面验证仍待后续完成。

前端检查：在 `frontend` 执行 `npm run build`（包含 TypeScript 检查）。后端检查：在 `backend` 执行 `uv run ruff check app migrations scripts`。

浏览器模块测试：在 `backend` 执行 `uv run python -m pytest -q`。

### 浏览器连接验证

1. 启动前后端，打开控制台，点击“启动 Chrome”。
2. 在打开的独立 Chrome 窗口中手动登录币安、处理验证。
3. 将实际使用的 `https://www.binance.com/` Alpha 链接粘贴到控制台，点击“打开页面”。
4. 点击“刷新状态”读取受控标签页的标题和地址。当前状态不代表已经识别登录成功或交易对。
5. 表单加载后再刷新状态，确认显示的币种、计价币与页面一致。输入指定价格、数量（代币单位）及方向，点击“仅填表并核对”。填表会核对链接中的链和合约地址、币种、计价币、方向与页面步长。
6. 检查控制台回读结果和 Chrome 表单。此功能没有下单按钮操作，也不通过回车提交。若弹窗遮挡、验证未完成、输入精度不符或页面变化，会停止并显示错误；可能已有部分字段被填写，请人工检查。

后端保持单 worker 运行，不启用 `--reload`。正常关闭后端会关闭受控浏览器，登录数据保留在 `data/browser-profile/`。如果执行器异常退出后 Chrome 仍留在桌面，请先手动关闭遗留窗口再重启，避免同一用户目录被占用。

## 模拟任务与成交账本

先执行 `uv run alembic upgrade head` 更新数据库，再按前述命令启动后端。在研究模块确认手续费并获取行情，点击“评估当前状态”会创建持久化模拟任务。使用手动成交、推进时间和撤单确认按钮测试流程。

历史任务支持载入，刷新后恢复上次任务；新建任务不删除历史。委托、成交、手续费和事件保存到本机 SQLite。页面显示累计买入额、预计积分、剩余持仓、已实现盈亏及预计浮盈亏。当前按任务累计，尚未设置每日自动重置或跨任务积分汇总。

默认目标 32,768 分，每 U 买入计 4 分，对应 8,192 U 买入成交额，卖出不计分。最后一单按最小委托和数量步长取整可能略超目标。达标或首笔买入成交后满 30 分钟即转主动退出，等待撤单确认后处理剩余持仓；不保证在时限内卖完。所有记录均明确为模拟，不接入账户真实订单。

## 真实订单账本（只读，费用估算）

执行 `uv run alembic upgrade head` 更新至迁移 0004，再启动后端。在独立 Chrome 登录并打开历史委托，按最新在前显示，展开第一笔以显示订单 ID，点击控制台“核对第一笔历史委托”。展开区域仅取 ID，不解析逐笔成交。当前不会自动展开、翻页或下单；缺少 ID 的行会提示跳过。

平台的已成交数量、成交均价、成交额与状态直接入账，不用均价重算成交额。相同账本内按订单 ID 更新，重复读取不重复累计；部分成交、撤单也按实际成交量统计，旧快照或累计量倒退不覆盖新记录。每侧手续费按成交额 × 0.01% 估算，预计积分仅为买入成交额 × 4。

切换平台账户时使用不同的账户账本名称，程序不自动识别账户身份。统计只代表已读取范围，按链/页面合约/币种/计价币分组累计，不自动按日重置。预计已实现盈亏按订单创建顺序及平均买入成本估算，缺失买入成本、同秒订单顺序不明或存在未结束订单时显示未知；不含持仓浮盈亏，也不是平台核定净盈亏。所有记录保存在被 Git 忽略的本机 `data/` 数据库，旧快照保留但不再新增或提供查询接口。

## 2026-09-22 单笔流程收敛

用户明确：没有人工订单穿插；系统同时只有一笔挂单、一个方向。主流程为系统记录本次委托 → 每分钟检查当前委托 → 委托消失后查询最新第一笔历史委托 → 核对币种、方向和本次委托关联后回填实际结果 → 下一笔。消失本身不作为全部成交依据，部分成交后撤销按实际成交汇总处理。

不做批量历史同步、自动翻页或逐笔成交解析。已将当前手动只读入口限制为历史列表第一笔；第一笔没有 ID 时停止，不跳过它去导入第二笔。列表需最新在前；这是手动核对工具，不是已接入系统委托的自动确认器。已有订单账本、去重、估算费用保留。真实提交、当前委托关联及一分钟自动巡检仍待实现，不将这次收敛描述为自动交易闭环完成。

## 实盘单笔入口（2026-09-22）

运行 `uv run alembic upgrade head` 升级到 0005，重启后端。新增“04 / 实盘单笔下单”，默认关闭；用户自行开启，填写方向、价格、数量，点击提交后程序执行一次真实按钮点击。买入含 0.01% 估算费用不超过 50 U，卖出按输入数量。这里不会自动产生下一笔订单，不是完整策略循环；下一笔需要用户点击“准备下一笔”。

程序先持久化委托和提交前最新历史 ID，再尝试提交。相同请求重试不再次点击；全局仅一笔未结束订单，结果未知时不接受第二笔。后端每 60 秒读取当前委托；有挂单则等待，明确为空才读第一笔历史汇总，核对新 ID、链/合约、币种、方向、委托价格和数量。最终已成交/已撤销等结果与账本在同一事务保存。页面加载、登录、控件或匹配失败时保留待核实，不把消失直接认定成交。

关闭实盘开关只阻止新单，不撤平台挂单；后端重启后开关关闭，恢复只读巡检而不重新提交。提交超时可能已送出，程序不会补点。未实现自动撤单、五分钟重挂、三十分钟主动退出与连续买卖策略；这些规则仍仅在模拟器中。

当前浏览器适配要求中文买卖按钮（例如“买入 DGAI”）、具有 `aria-controls` 的当前/历史委托标签和明确的空状态。无法匹配即停止；验证码和额外交易确认弹窗交由用户处理，不自动连点确认。真实登录页选择器与实际提交尚未验收，隔离页面测试通过不代表平台实盘测试通过。
