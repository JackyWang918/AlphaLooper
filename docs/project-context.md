# 项目目的与接续说明

最后整理：2026-09-21。本文用于跨电脑、跨 Codex 会话继续项目，无需用户重复背景。实际代码能力以当前仓库与验证结果为准。

## 1. 用户为什么做这个项目

用户每天参与 Binance Alpha 交易积累积分。目前需要花时间手动反复买卖，为了尽快完成任务有时交易损耗较大，曾出现一天损耗超过 10 U 的情况。用户描述为“被夹”，但尚未通过交易记录区分链上夹子、价差、滑点或价格波动等具体原因，不应直接下定论。

用户希望构建一个浏览器自动交易辅助程序：通过行情数据和规则计算价格，自动输入价格、数量并执行买卖；订单一定时间未成交时，能按规则撤单调整，避免一直买不到或卖不出。长期希望晚上运行，减少重复劳动与赶时间交易带来的损耗。

用户不是始终交易同一个币。某些币的 4 倍活动有时限，当前人工寻找适合当天交易的币，因此必须允许手动修改交易币种或链接，不将 DGAI 固定为唯一交易对象。

## 2. 用户已明确的工作方式

- 用户自己登录，出现风控验证时自己处理。
- 初期可以约半个月守着电脑验证，不要求一开始就无人值守。
- 初期最关心的是浏览器能否受控：把其他程序算出的价格和数量填入页面，执行买卖操作。不要把账户信息获取再次当成唯一的首要问题。
- 行情计算、浏览器执行可以是独立模块，通过指令连接。
- 用户希望有数据展示和交互界面。
- 前后端放在同一个项目文件夹、同一个 Git 仓库中。
- Python 用 uv；前端用 npm；本地 SQLite3；源码运行，暂不考虑部署或打包。
- 2026-09-21 用户在公司，不方便频繁操作界面，登录后的测试留到回家继续。此为当时安排，不是永久禁止测试。

## 3. 策略方向与最新决定

用户已澄清：根据过去的数据估算合理买卖价格，挂单等待；超时未成交就撤销、重新估价并重挂。不是以快速买卖作为默认策略。详细规则与尚待确认的细节见 [首轮策略约定](strategy.md)。

助手建议的优先顺序为：避免误操作和失控持仓 → 控制损耗 → 完成目标有效交易量 → 缩短时间。这个顺序尚未得到用户明确确认，不得作为已经敲定的策略。

最新已确定：每轮 50 U；等待时间初值 5 分钟；买入允许追随新行情重估；卖出能回本时参考卖一，未回本时重算卖价；亏损阈值 2%，每分钟结束后检查；触发后允许根据最新买盘持续调整至卖完；整场测试累计损耗预算不超过 10 U。用户举例以买盘第 6 档作为主动卖出价格。

其他尚未确定的参数和口径：

- 每日目标积分或有效买入量，整场测试损耗与每日损耗的关系。
- 更精确的费用来源、真实执行损耗和预算预留参数。用户已确认损耗含费用与预计退出浮亏，预算触发后停止新买入并处理已有持仓。
- 夜间运行窗口、最长持仓时间、任务截止时间。
- 历史窗口、波动算法和报价偏移参数待实验；用户已确认每张普通单 5 分钟，部分买入到期后先卖已有数量、不补足。
- 主动退出重挂间隔、买盘不足六档或深度不足的实盘处理；模拟阶段的试验规则见策略文档。
- 活动倍率和有效期如何核实、过期如何处理。

不要把未定细节当作已确认，也不要承诺一定成交或绝对损耗上限。

## 4. 已实现的程序能力

- FastAPI 后端与 Vue 3 + TypeScript + Vite 控制台。
- 通过 Playwright 独立进程启动本机 Chrome，使用 `data/browser-profile/` 保存本地登录数据。
- 控制台输入 Alpha 链接，打开受控标签页，查询标题和地址。
- 读取中文 Alpha 表单中的代币、USDT/USDC 计价币、买卖方向与输入步长。
- 仅填表：核对目标链和合约、币种和计价币，切换方向，填写价格与代币数量，再回读核对。
- 遮挡弹窗、币种不符、精度不符、方向变化等异常会停止操作；不强行穿过遮挡层。
- 页面操作串行执行，忙时拒绝其他操作；刷新控制台不会重放指令。
- SQLite 和 Alembic 基础设施已创建，但业务订单、成交与任务历史表尚未实现。

新增：公开行情接入，已收盘 1 分钟 K 线、成交量、盘口展示，参数化挂价试算，以及显式成交事件驱动的订单流程沙盒（超时、部分成交、分钟损耗检查、主动退出及预算限制）。仅模拟，并未连接浏览器下单。控制台反馈和沙盒状态保存在当前页面内存，刷新会重置。

当前没有：真实订单提交、真实订单/成交监听、真实撤单重挂、自动实盘循环、自动选币、积分计算、持久化指令队列或 WebSocket 状态推送。

不要将可见的买卖切换 tab 当作最终买卖提交按钮。当前代码不定位或点击最终提交按钮；未登录时该区域显示登录入口。

## 6. 当前样例币及公开行情验证

用户提供的真实交易页面：

https://www.binance.com/zh-CN/alpha/bsc/0x10d4183389e99233db3cc981c43443ebd28ebd5e

2026-09-21 官方公开接口匹配结果：

| 项目 | 值 |
| --- | --- |
| 名称 / 币种 | DGrid AI / DGAI |
| 链 | BSC，chainId 56 |
| 合约 | `0x10d4183389e99233db3cc981c43443ebd28ebd5e` |
| Alpha ID | `ALPHA_1185` |
| 本次测试交易对 | `ALPHA_1185USDT` |

已经实际在不登录、不提供 Cookie 或 API Key 的情况下获取到 1 分钟 K 线、盘口和 24 小时 ticker，并集成进应用。BSC 交易链接映射、行情与策略研究界面已经使用真实 DGAI 数据验证。尚未验证策略实盘效果。

官方文档：https://developers.binance.com/en/docs/catalog/advanced-trading-alpha-trading/api/rest-api/market-data

基地址：`https://www.binance.com`

```text
GET /bapi/defi/v1/public/wallet-direct/buw/wallet/cex/alpha/all/token/list
GET /bapi/defi/v1/public/alpha-trade/get-exchange-info
GET /bapi/defi/v1/public/alpha-trade/klines?symbol=ALPHA_1185USDT&interval=1m&limit=5
GET /bapi/defi/v1/public/alpha-trade/ticker?symbol=ALPHA_1185USDT
```

先用链与合约匹配代币，再用 exchange-info 确认计价交易对，不能只靠币名或拼接未经验证的 symbol。

K 线数组字段：开盘时间、开、高、低、收、基础币成交量、收盘时间、计价币成交额、成交笔数、主动买入基础币量、主动买入计价币额、占位字段。最新一根可能尚未闭合。ticker 的 `volume` 是基础币数量，`quoteVolume` 是计价币成交额；这不是账户成交量或积分有效交易量。

当时 `data/dgai-klines.json` 和 `data/dgai-ticker.json` 保存了本地样本，`data/` 被 Git 忽略，家里电脑不会自动收到这些文件。如需样本，请重新请求。

网络实测：公司机器直连 Python 请求 DNS 失败，Python 经代理请求曾遇到 TLS EOF；Windows `curl.exe --proxy http://127.0.0.1:7897` 成功。未关闭 TLS 校验。家里网络需重新检查，不能把公司代理地址硬编码为必需条件。

## 8. 家里电脑的接续方式

仓库：https://github.com/JackyWang918/AlphaLooper ，主分支 `main`。

1. 克隆或拉取仓库，让 Codex 先读根目录 `AGENTS.md` 和本文。
2. 安装 uv、Node.js/npm 和 Chrome，按 README 同步依赖并迁移数据库。
3. 默认后端端口 18760、前端端口 18761；当初为了避开公司电脑的 8000/5173 占用而选择。更改端口需同步前端代理和后端允许的 Origin。
4. 浏览器登录状态和数据库只在各自电脑本地；家里应重新登录，不通过 Git 传递 Cookie。
5. 后端单 worker，无自动重载；关闭/重启后端可能关闭受控 Chrome。

当前源码开发环境为 Python 3.12 + uv、FastAPI、Playwright；Vue 3 + TypeScript + npm；SQLite + SQLAlchemy + Alembic。更多启动命令见 README。

Git 推送的公司网络备用命令：

```powershell
git -c http.proxy=http://127.0.0.1:7897 push
```

这是单次命令代理，不应未经核实更改家里机器的全局 Git 配置。
